### 3.2 Yeni modül A — `agent_core/services/profile_router.py` (saf sınıflandırma)

**Sorumluluk:** yalnız URL → (platform, handle, capability_id, reason). **I/O YOK, ağ YOK, yan etki YOK.**

| Fonksiyon | Sözleşme |
|---|---|
| `classify_url(url: str) -> ProfileRoute` | tek URL sınıflandırır |
| `plan_for_urls(urls: Iterable[str], *, limit: int = 3) -> list[ProfileRoute]` | yinelenen URL'leri eler, sıra korur, `limit` uygular |

**`ProfileRoute` alanları** (Pydantic, `agent_core/domain/` veya modül içi):

| Alan | Tip | Anlamı |
|---|---|---|
| `url` | `str` | kaynak URL (kanıtta görünür) |
| `platform` | `str` | `instagram` \| `x` \| `web` \| `unsupported` |
| `handle` | `str` | çıkarılan kullanıcı adı (boş olabilir) |
| `capability_id` | `str` | hedef yetenek (yoksa boş) |
| `reason` | `str` | neden yol yok (`not_a_profile_url`, `unsupported_platform`, `duplicate_url`) |
| `runnable` | `bool` | `capability_id` dolu **ve** handle dolu |

**Yol tablosu (tasarım kararı):**

| URL kalıbı | capability | Gerekçe |
|---|---|---|
| `instagram.com/<kullanıcı>` | `sensor.ig.instagrapi` | `extract_username` yalnız gerçek profil URL'si kabul eder |
| `x.com/<kullanıcı>` / `twitter.com/<kullanıcı>` | `sensor.x.twscrape` | `extract_x_username` |
| `linkedin.com/in/…`, `linkedin.com/pub/…`, `facebook.com/…` | `extractor.identity.socid` | profil kimlik alanı çıkarımı — bulgu 3'ün ölü kodunu bu hatta bağlar |
| diğer / rezerv segment / etiket sayfası | — | `runnable=False` + `reason` |

**Reddedilen alternatifler (gerekçeyle):**
* ❌ **`api.py:2617`'deki sabit alan listesini genişletmek** — alan listesi sınıflandırma değil, eşleştirmedir; "x.com.evil.com" gibi alan adı taklidi riski taşır. `platform_registry` zaten **host** tabanlı çalışıyor (`_is_instagram_host`, `extract_x_username` host kontrolü) → **host tabanlı sınıflandırma** kullanılır.
* ❌ **Sınıflandırmayı `backend/api.py` içinde yazmak** — tavan ihlali + test edilebilirlik kaybı.
* ❌ **`detected_urls`'ı doğrudan `run_capability`'a vermek** — yeteneğin **hangi** olduğu kararı kaybolur; "neden bu sensör?" sorusu cevapsız kalır.

### 3.3 Yeni modül B — `agent_core/services/profile_deep_scan.py` (koşum)

**Sorumluluk:** `ProfileRoute` listesini `CapabilityRunner` üzerinden koşmak; sonucu **kanal durumu + kanıt** olarak döndürmek.

| Fonksiyon | Sözleşme |
|---|---|
| `run_plan(routes, *, state=None, runner=None) -> DeepScanResult` | her route için yeteneği koşar |
| `DeepScanResult` | `channel_runs: list[ChannelRun]`, `evidence_items: list[EvidenceItem]`, `scraped: dict[url, dict]` (yalnız **gerçekten kazınan** alanlar) |

**Çalıştırma kuralları:**
1. `CapabilityRunner` dışında **doğrudan yetenek çağrısı yok** (`runner.py:29` tek geçit).
2. `policy_state(vault_locked=..., rate_ok=...)` **çağıranın mevcut kasa/hız durumundan** gelir → kasa kilitliyken koşum başlamaz (kapı zayıflatılmaz).
3. Kapasite `not available` → `not_run(reason=<makine-okunur sebep>)`. **`policy:gate_disabled` / `no_session_pool` / `dependency_missing:*` / `policy:vault_locked` aynen aktarılır.**
4. Koştu ama kanıt üretmedi → `not_run(reason=...)` (**boş liste dönmez**).
5. **Sessiz snippet düşüşü yok:** derin tarama başarısızsa `posts` **boş kalır**; `search_snippets` + `content_basis=search` korunur (P0 sözleşmesi).
6. **Egress bozulmaz:** modül `httpx` import etmez; dışa çıkış yalnız yeteneğin kendi `egress.open_client` çağrısıyla olur. Test bunu kilitler.
